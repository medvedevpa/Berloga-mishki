# v15 — отдельные объёмные модели и новая доставка обновления

В этом выпуске переработаны модели, которые видны непосредственно во время игры. Обложки и канонический мишка Матвей сохранены.

## Графика в самих играх

**Кафе.** Новый зайчик-повар создан в Blender и загружается как GLB-модель: непрерывная форма головы с объёмными щёками, изогнутые сужающиеся уши, крупные многослойные глаза с бликами, мягкая улыбка, лапки с пальцами, фартук, лямки, пуговицы, карман и цветочная вышивка. Для головы, ушей, глаз и лап сохранены отдельные узлы анимации. Персонаж увеличен в сцене, камера смотрит на него под более пологим углом.

Яблоко, морковь и груша тоже заменены отдельными моделями. Яблоко имеет цельную форму, углубление у черенка и лист; морковь — органический сужающийся корнеплод, бороздки и ботву; груша — широкую нижнюю часть и узкую шейку. Корневые объекты перетаскивания и зоны выбора сохранены.

**Посылки.** Три домика получили общую подробную модель с индивидуальными цветами крыш. Скруглённая черепица, труба, штукатурные стены, деревянные углы, дверь с фактурными планками и ручкой, окна с переплётами, цветочными ящиками и круглая мансарда находятся в самой 3D-сцене. Символы нужного подарка остаются видимыми перед фасадом.

**Сад.** Новые модели подсолнуха, клубники и гороха включают изогнутые стебли, выгнутые листья с прожилками, два слоя лепестков и отдельные семечки подсолнуха, клубнику с семенами и зелёной коронкой, объёмные стручки и горошины. Рост, выбор урожая и перенос в корзину используют прежние игровые состояния. Во время полива касание листьев текущего растения также засчитывается как выбор его горшочка.

Цвета игрушек в посылках сделаны насыщеннее. Базовые иллюстрации мишки и иконки PWA не менялись.

## Модели и исходники

Все модели сделаны локально скриптом `tools/build-models.py` в Blender 4.3.2. Это авторская геометрия проекта, без скачивания моделей или обращения к сервисам генерации во время игры.

| Файл | Содержимое |
| --- | --- |
| `assets/models/bunny-chef-v15.glb` | Зайчик с узлами анимации |
| `assets/models/produce-v15.glb` | Яблоко, морковь, груша |
| `assets/models/cottage-v15.glb` | Домик; цвета крыш назначаются по получателю |
| `assets/models/sunflower-v15.glb` | Подсолнух |
| `assets/models/berry-v15.glb` | Клубника |
| `assets/models/pea-v15.glb` | Горох |
| `js/sculpted-models.js` | Загрузка и подключение к существующим интерактивным корням |
| `js/vendor/gltf-loader.min.js` | Локальный GLTFLoader Three.js, та же MIT-лицензия |

Модели вместе занимают около 5,5 МиБ. Геометрия объединена по материалам внутри каждого узла анимации, чтобы многочисленные детали не создавали отдельный вызов отрисовки на каждое семечко. Пока модель загружается, остаётся рабочая упрощённая геометрия. Если сцена закрылась до загрузки, пришедшие ресурсы освобождаются. Все модели включены в офлайн-комплект.

Пересборка моделей: `npm run models:build` (нужен установленный Blender). Затем `npm run build`. В Blender используется Z вверх; экспорт GLB преобразует координаты в Y вверх для Three.js.

Сохранять имена узлов: `HeadRig`, `EarLeftRig`, `EarRightRig`, `EyeLeftRig`, `EyeRightRig`, `ArmLeftRig`, `ArmRightRig`, `PlantBody`, `Harvest`. Они связывают модели с анимацией и игровыми действиями.

## Почему изменена публикация

В прежнем Service Worker статические файлы искались с `ignoreSearch`. Это могло вернуть старый скрипт для нового запроса с `?v=...`. Поэтому одного изменения query-параметра было недостаточно для гарантированного получения новой графики.

Теперь `npm run build` создаёт готовые файлы с отдельными путями и хэшами содержимого:

- `js/release/v15/app-*.js` и общие динамические chunks;
- `css/stylesheet-v15-*.css`.

HTML загружает их по новым адресам, которых нет в старом кэше. При установке новой версии Service Worker заново проверяет ресурсы с `cache: reload`. Отдельная стартовая страница `release-v15.html` записывается в офлайн-кэш также как главная и `index.html`; прежний worker не может выдать вместо неё старый файл по совпадающему адресу. Сначала новый worker принимает управление вкладками, затем удаляются старые кэши. В офлайн-кэш входят актуальные готовые файлы, CSS и изображения/модели. Данные в localStorage/IndexedDB не очищаются.

Исходники по-прежнему разделены: редактируются соответствующие файлы в `js/` и `css/`, игровые данные — в отдельных `*-data.js`, модели — в `assets/models/` и скрипте Blender. Сгенерированные файлы выпуска вручную не править. Это статический сайт: для запуска опубликованного приложения сборка, npm и Blender не нужны.

Разработка: `npm ci`, затем после правки `npm run build`. При добавлении ресурсов генератор кэша вызывается автоматически. Сборка выполняется esbuild с локальными зависимостями; внешних runtime-скриптов и аналитики нет.

## Проверки

Подтверждено в Chromium (Linux):

- Полный `npm test` проходит на готовом выпуске: основные разделы, 12 игр школы, все три угощения кафе, все посылки и растения, награды, перетаскивание, перезапуск, ручные переходы, офлайн и восстановление графического контекста.
- Проверки 3D-игр дожидаются загрузки новых GLB, а не оценивают только временную геометрию. Подтверждены все шесть файлов без ошибок загрузки.
- Все три сцены осмотрены на ширинах 320, 390, 768 и 1280 px, без горизонтального переполнения.
- В отдельной копии сайта установлен настоящий прежний Service Worker v14. Затем файлы заменены v15: новая стартовая страница загрузила актуальные JS/CSS и GLB, сохранились 23 тестовые звезды, пометка карточки и голосовой Blob в IndexedDB. После завершения активации новая графика сада работает офлайн.
- Ошибок JavaScript и HTTP-загрузки в завершённых сценариях нет.

Логические 3D-прогоны на программном GPU выполнялись с уменьшением движений для устойчивости тестов. Отдельный прогон без уменьшения движений подтвердил, что импортированный персонаж анимируется (кадры canvas меняются). Нативное касание с удержанием 1,2 секунды выбрало новую модель яблока; переход по «Дальше» выполнен касанием. Отдельно проверены полив и рост новой модели растения.

 Реальные iPhone/iPad и частота кадров на них отдельно не проверялись. Это подробная стилизованная графика; уровень рендера коммерческой игры с исходного референса не заявляется.
