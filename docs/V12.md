# v12 — «Лесное кафе», отдельная 3D-игра

На главной появилась кнопка **«Лесное кафе · 3D»**. Это интерактивная WebGL-сцена: геометрические модели фруктов, посуды, кухни и зайчика, освещение, тени, попадание лучом по предметам и перемещение в трёхмерном пространстве. Мишка Матвей остаётся канонической иллюстрацией-проводником; новый объёмный персонаж — зайчик, не замена мишки.

## Игровой цикл и речевая цель

Три угощения: яблоко, морковь, груша. Для каждого — четыре шага:

| Действие | Речевая модель | Реальная игра рядом со взрослым |
| --- | --- | --- |
| Выбрать нужный продукт на подносе | ДАЙ / «Дай яблоко» | Открытая ладонь, просьба настоящей игрушки |
| Перенести в мойку и провести по воде | КАП-КАП / МОЙ / «Мой яблоко» | Сухая и влажная салфетка, совместное мытьё фрукта |
| Водить пальцем и помешивать ложкой | МЕШ-МЕШ / МЕШАЙ / «Мешай салат» | Настоящая миска и деревянная ложка |
| Взять миску и передать зайчику | АМ-АМ / НА / «На, зайчик» | Покормить игрушечного друга, попросить «ЕЩЁ» |

У каждого шага есть озвучка и её повтор, ручной переход и пауза для слова/звука/жеста. Неверный выбор вызывает мягкую подсказку. Без ответа переходов нет; после успеха «Дальше» доступна не раньше трёх секунд от начала шага. Взрослый может отметить попытку кнопкой «Мы попробовали!», но игра не проверяет качество произношения и не запрашивает микрофон.

На экране доступны перетаскивание, движения по воде/миске и крупные кнопки для тех же действий. Лёгкую вибрацию можно включить вручную на устройствах, где доступен Vibration API. На iPhone эта возможность обычно отсутствует. Экран не передаёт фактуру, температуру или сопротивление реального предмета: настоящие тактильные ощущения дают предложенные занятия вне экрана. Монтессори-подход служит вдохновением для самостоятельных простых действий; игра не является медицинской терапией.

За каждое завершённое угощение начисляется одна игровая звезда; повторное нажатие её не дублирует. Существующие семейные жетоны за реальные действия взрослый отмечает отдельно.

## Файлы и запуск

- `js/picnic-launcher.js` — ленивый вход с главной.
- `js/picnic-data.js` — продукты, слова трёх уровней и идеи для взрослого.
- `js/picnic-game.js` — состояния, доступные кнопки, озвучка, паузы и завершение.
- `js/picnic-scene.js` — модели, материалы, анимации, raycasting, drag/cancel и очистка ресурсов.
- `css/picnic.css` — отдельный интерфейс игры для телефонов, планшетов и ПК.
- `js/vendor/three.min.js` — локальная Three.js r182; лицензия MIT рядом в `THREE-LICENSE.txt`.
- `tools/vendor-three.cjs` — воспроизводимая сборка библиотеки (`npm ci`, `npm run vendor:three`). При обычном запуске приложения npm не требуется.
- `tests/picnic.cjs` — сценарии новой игры.

Библиотека и код загружаются при входе в игру с того же сайта. CDN, аналитики, серверов и сетевых API в игре нет. Полный комплект включён в Service Worker v12; обход файлов в генераторе кэша теперь рекурсивный, чтобы не пропустить `js/vendor/`.

Существующий движок предоставляет узкий `MatveyGameBridge`: показать экран, остановить предыдущую игру, произнести фразу с текущими настройками, сыграть звук, добавить звезду и вернуться домой. Схемы localStorage и IndexedDB не менялись; добавляется только счётчик `picnicServed` при выдаче звезды.

Для игры нужен WebGL2. При недоступном или потерянном графическом контексте показываются повторный запуск и возможность вернуться домой. При выходе удаляются обработчики, ResizeObserver, геометрии, материалы, текстуры, WebGL-контекст и цикл отрисовки. При скрытой вкладке отрисовка приостанавливается; при уменьшении движений нет покачиваний, вспышек и перелётов. Плотность пикселей ограничена, тени статичных объектов не пересчитываются на каждом кадре.

Локально: `python3 -m http.server 8765`. Проверки: `CHROMIUM_PATH=/usr/bin/chromium npm test` для установленного Chromium либо `npx playwright install chromium`, затем `npm test`. Сайт по-прежнему размещается без сборки в GitHub Pages.

## Проверки и ограничения

Результаты Chromium записаны после прохождения сценариев в конце этой страницы. Настоящие iPhone/iPad, их производительность, системная озвучка и вибрация физического устройства требуют отдельной проверки. Процедурная стилизованная графика не повторяет качество моделей и анимации коммерческой игры с референса.

## Подтверждённые результаты Chromium

- Реальный WebGL2-контекст, объёмные модели и рабочее попадание лучом по фрукту.
- Ширины 320, 390, 768, 1280 px без горизонтального переполнения.
- Нет перехода при бездействии; неправильный продукт не завершает шаг.
- Перенос фрукта в мойку мышью, мытьё и перемешивание кнопками, завершение всех трёх угощений.
- Одна звезда за угощение; повторное нажатие после успеха заблокировано.
- «Дальше» недоступна до минимального времени, затем ждёт ручного нажатия.
- Перезапуск, несколько входов/выходов, один canvas при входе и отсутствие canvas после выхода.
- Искусственная потеря WebGL-контекста, экран ошибки и восстановление по кнопке.
- Отдельная проверка браузера с выключенным WebGL: понятное сообщение и работающий выход домой.
- Уменьшение движений, отмена перетаскивания через pointercancel, офлайн-перезагрузка и повторный вход в 3D.
- Старые smoke/regression-проверки приложения прошли: основные разделы, 12 игр школы, сортировка, пометки карточек, семейные награды и офлайн-режим.
- Нет ошибок JavaScript и HTTP-загрузки ресурсов в проверенных игровых сценариях.

Для WebGL-проверок в Linux использовался Chromium с программным рендерером SwiftShader. Это проверка работоспособности, а не измерение частоты кадров на телефоне.
